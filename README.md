# 车镜 CarMirror

把荣耀手机画面实时投到领克 09（OSN 2.0 / Android 9 / 8155）车机上。**不依赖 ADB、不依赖车机原生互联协议、不依赖任何第三方 App 白名单。**

一个仓库两个 APK，纯 Java，无第三方依赖：

| 模块 | 装在哪 | 干什么 |
|---|---|---|
| `phone` | 荣耀手机 | `MediaProjection` 抓屏 → `MediaCodec` 编 H.264 → TCP 推流 |
| `car` | 领克 09 车机 | TCP 拉流 → `MediaCodec` 硬解 → 全屏 `SurfaceView` 渲染 |

已在 GitHub Actions 真实构建通过：最新一次 run `41942905858`（`carmirror` 分支，v1.0.3），结论 `success`，产出两个 debug 签名 APK，可直接侧载：

## 为什么必须自建

荣耀车联连这台车（HiCar 通道）本身是通的，但它的模型是"白名单应用 + 手机版界面塞进车机桌面"：

- ICCE 通道应用多（60+），本车机不支持，用户已实测确认；
- HiCar 2.0 老通道的"添加更多应用"白名单由厂商云端配置，自己写的 App 和名单外的 App 一律投不上去；
- 车机有 HiCar ≠ 荣耀手机能用它当"任意画面投屏管道"，它从设计上就不提供这个能力。

所以唯一不封顶的路径是：绕过厂商互联协议，自己搬像素。

已被验证走不通、不要重复尝试：`Easycontrol_For_Car`（卡在车机侧 ADB host/授权链路）、Miracast sink（Android 8.0 起需要 OEM/系统签名，普通 APK 装不上）、`HeadunitRevived`（需 GMS）、`DiPlay/DiAuto`（面向 iPhone/BYD）。

## 通信协议

手机监听 **7801**，车机主动连。全部大端。

握手（服务端 → 客户端）：

```
byte[4] magic = "CMSH"
int32   version = 1
int32   width
int32   height
int32   csd0Len + csd0 bytes     // SPS
int32   csd1Len + csd1 bytes     // PPS
```

之后逐帧：

```
int32   flags
int32   length
byte[length]
```

- `flags = 0`：普通视频帧，payload 是 Annex-B H.264
- `flags = 1`：关键帧
- `flags = 2`：参数更新 `int32 w, int32 h, int32 csd0Len+csd0, int32 csd1Len+csd1`——手机转屏、游戏进横屏后编码尺寸变了就发这一条，车机收到后重建解码器

音频走另一条连接 **7803**（同一个手机 IP）：

```
int32   sampleRate      // 44100
int32   channels        // 2
int32   csdLen + csd    // AudioSpecificConfig
之后：int32 length + byte[length]   // AAC 裸帧
```

设计要点：

- 每帧 `flush()`，优先低延迟而不是吞吐；
- 发送队列深度 6，满了丢非关键帧、关键帧覆盖旧帧，避免慢网络把编码器拖死；
- 新连接进来会踢掉旧连接，换设备/重连不会卡死；
- 车机接入时手机侧 `PARAMETER_KEY_REQUEST_SYNC_FRAME` 立刻强制一个 IDR，避免空白等待；
- 编码参数：长边 ≤ 1920、对齐 16、30fps、8Mbps CBR、I 帧间隔 1s。

## 编译

### 方式 A：GitHub Actions（推荐，无需本地 Android 环境）

推上仓库即可，`.github/workflows/build.yml` 会产出 `carmirror-apks`（artifact 里两个 debug APK）。

```
gradle :phone:assembleDebug :car:assembleDebug
```

### 方式 B：Android Studio / 本地

用 Android Studio 打开本目录直接 Run。工程版本组合：**AGP 8.1.3 + Gradle 8.0 + compileSdk 34 + minSdk 21 + Java 8 + JDK 17**（与既有车机工程一致，已验证可用）。

工程已通过云端构建验证；本机无 Android SDK，本地直接用 Android Studio 打开即可。

## 使用

手机端：

1. 装 `phone` APK，打开，授予通知权限。
2. **建议先开手机热点，让车机连这个热点**（车机连手机热点，延迟和稳定性都比两个设备连同一个路由器好）。
3. 点"开始投屏"，首次会先要**录音权限**（内录游戏声音用，允许才有声），再弹录屏授权 → 都允许。

> 签名已经固定，从 v1.0.3 起新版本可以直接覆盖安装，不用再卸载。证书 SHA-256 指纹：
> `B0:07:8A:A1:E0:D5:E6:7C:60:EC:E7:82:18:BF:45:34:2E:01:EB:5A:5F:CD:43:4C:3A:95:59:F2:34:9B:81:D8`
> 每版都应一致；装包前若发现不一致，说明不是同一把密钥签的。
4. 界面会列出本机所有网卡地址（同时连 Wi-Fi 又开热点时会有两条），**不用记**——车机会自己找。
5. 投屏期间**不要锁屏**（锁屏后画面会中断），可以把亮度调低。
6. 想投横屏内容，就把手机横过来再点"开始投屏"——编码分辨率按启动瞬间的方向确定，中途转屏会变形，需要停止后重连。

车机端：

1. 把 `car` APK 侧载进车机（U 盘 + 应用管家，或 adb install）。
2. 打开，点**"自动查找"**，找到手机后自动连接。找不到再手动填手机端 `ap` 那行的地址。
3. 连接成功后控制条 3 秒自动隐藏，点屏幕任意位置可再唤出。
4. 画面按比例居中，两侧黑边是正常的（手机和车机屏比例差太大）。

## 发现机制

两端不再靠人工抄 IP：

- 手机端在 UDP **7802** 上待命，收到任何包就回 `CARMIRROR:7801`；
- 车机端点"自动查找"时向 `255.255.255.255:7802` 广播，**用回复包的源地址**当手机地址，然后直接连 7801。

这么做的原因：手机同时连着 Wi-Fi 又开热点时，`NetworkInterface` 往往只报出 Wi-Fi 的地址，荣耀的 SoftAP 网卡还可能根本枚举不到。让手机自己猜"我的热点 IP 是多少"必然出错，让车机从实际收到的包反推则不会错。

代价是要求两台设备在**同一个广播域**（车机连手机热点，则天然满足）。如果车机是通过路由器中继、或热点开了客户端隔离，广播到不了，就退回手动填地址。

## 已知限制

- **锁屏即断**：`MediaProjection` 抓的是屏幕内容，熄屏就没有画面。真要做"熄屏投屏"得另走虚拟显示方案，不在这一版。
- **断线不自动重连**：车机端点一次"连接"即可；重连会重新请求关键帧。
- **声音是内录的，有条件**：走 `AudioPlaybackCapture`（Android 10+），只抓"系统正在播放的音频"，所以游戏 BGM/音效可以，麦克风里的说话不会过去。被投屏的 App 如果自己声明了禁止被内录（少数游戏会），那它还是没声音。另外必须授予录音权限，否则只有画面没有声音。
- **触摸反向控制没有**：车机只能看，不能操作手机。
- **延迟预期**：同一 Wi-Fi 下 100~200ms 量级，热点直连更低；Wi-Fi 干扰大时会卡顿掉帧。
- **首次授权**：荣耀手机重启后首次投屏需要重新授权一次，这是系统行为，绕不过。
- **编码方向**：按启动瞬间屏幕方向定分辨率，中途转屏画面会被压扁，需停止再开。

## 版本约定

改车机端代码后，`car/build.gradle` 的 `versionCode` / `versionName` 必须同步递增，并在更新信息里写清楚改了什么，车机才能提示更新。
